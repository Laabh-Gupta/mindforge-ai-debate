tell me how to configure the supabase

1
Create a Supabase project
Go to supabase.com/dashboard, sign in, and click "New project". Pick an organization, name it (e.g. "mindforge"), set a database password (save it somewhere — you likely won't need it day-to-day, but it's needed for direct Postgres access), and pick a region close to you. Wait ~2 minutes for it to provision.
2
Grab your API URL and anon key
In your new project, go to Settings → API. Copy the "Project URL" and the "anon public" key (not the service_role key — that one must never go in a browser-exposed env var). Paste them into your .env file as VITE_SUPABASE_URL and VITE_SUPABASE_ANON_KEY.
3
Run the schema migration
Open the SQL Editor (left sidebar) → New query. Paste the full contents of supabase/schema.sql from the repo and click Run. This creates the skill_records table, its index, and the row-level-security policies that keep each user's history private to them.
4
Turn on email/password auth
Go to Authentication → Providers. "Email" is enabled by default — that's all login.tsx/signup.tsx need for password sign-in. Under Authentication → Settings, you can decide whether "Confirm email" is required before a new signup gets a session (if it's on, new users need to click a confirmation link before they can log in).
5
Enable Google sign-in (optional)
Only needed if you want the "Continue with Google" button to actually work. In Google Cloud Console, create an OAuth 2.0 Client ID (type: Web application), and add https://<your-project-ref>.supabase.co/auth/v1/callback as an authorized redirect URI. Copy the Client ID and Secret into Supabase's Authentication → Providers → Google. If you skip this step, the Google button will just show an error — email/password will still work fine.
6
Add your site URLs
In Authentication → URL Configuration, set your Site URL (e.g. http://localhost:3000 for local dev, or your deployed domain later), and add it to Redirect URLs too. This is what Google OAuth and email confirmation links redirect back to — auth.ts already sends people to /dashboard after Google sign-in, so make sure that path exists under whichever URL you set here.
7
Restart the dev server
Vite only reads env vars at startup, so after editing .env, stop and re-run bun run dev. Try signing up with a test email — you should land on /dashboard, and after finishing a debate/session, a new row should appear in skill_records under Table Editor in Supabase.
A couple of things worth flagging as you go through this:

The service_role key (also on the Settings → API page) should never end up in VITE_-prefixed env vars or anywhere client-side — only the anon key belongs there. RLS is what keeps the anon key safe to expose.
If email confirmation is on and you test signup yourself, check your inbox (or Supabase's Auth → Users list, where you can manually confirm a test user) before assuming login is broken.
Skip step 5 entirely if you don't care about Google login right now — it's the only optional one.
